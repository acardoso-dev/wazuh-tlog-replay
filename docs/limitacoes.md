# Limitações conhecidas

- **Menu do agente e card da home:** o Wazuh dashboard não permite que outros plugins adicionem itens a essas telas, então o plugin os insere na página, sem alterar arquivos da plataforma Wazuh. O card é um clone do **IT Hygiene**. Uma atualização pode fazer os itens sumirem; o app continua acessível pela sidebar. O item do agente não pode ser fixado como as abas nativas.
- **Sessões por agente:** a ligação usa o hostname do inventário de agentes Wazuh, comparado com o `host` gravado pelo tlog. Se forem diferentes, como nome curto e FQDN, as sessões não aparecem. Se duas máquinas tiverem o mesmo hostname, as sessões delas se misturam. Um agente recém-registrado pode levar alguns minutos para entrar no inventário.
- **Sessões longas:** cada replay carrega no máximo 20.000 pedaços ou 64 milhões de caracteres, e avisa quando corta o restante. O servidor analisa até 6 gravações ao mesmo tempo, e responde 429 quando há mais de 200 esperando. A lista de comandos críticos de uma sessão mostra até 200 eventos e avisa quantos ficaram de fora.
- **Comandos críticos:** a busca lê o eco do terminal, só em linhas com um dos formatos de prompt ligados nas configurações. Ela não vê `ssh host comando`, scripts, conteúdo ofuscado (um `rm` em `base64 | sh` aparece só como pipe para shell) nem prompts personalizados fora desses formatos, como `❯`. **Nenhum evento não prova que nada crítico aconteceu.** Um comando listado foi digitado, mas pode ter falhado. Usar Tab para listar opções pode repetir um item.
- **Ligação com os alertas:** não há identificador comum entre o alerta e a sessão. A ligação usa máquina, usuário, comando e horário de chegada ao Wazuh manager. Sessões simultâneas do mesmo usuário ou um agente que ficou offline podem deixar alertas sem ligação. O salto SSH só é reconhecido na mesma máquina; entre máquinas, o destino mostra apenas o IP de origem.
- **Evidência mais forte com `auditd`:** o campo `session` do tlog parece ser o mesmo `ses=` do `auditd`, o que ligaria cada comando executado à sessão exata. O Wazuh manager interpretou esse campo em uma linha de exemplo (regra 80792), mas o fluxo completo e o volume de alertas não foram testados, porque o contêiner de teste não permite `auditd`.
- **Relógio do player:** o player encurta as pausas para no máximo 2 s, ou o valor configurado, então o tempo mostrado nele não é a duração real. O salto usa marcadores, que acompanham esse encurtamento. O horário real está no título do replay.
- **Timeline:** mostra o início, os trechos com dados gravados e as pausas a partir do tempo configurado (30 s por padrão). O fim vem do alerta de encerramento do SSH, quando existe. Sem ele, é a última saída gravada, porque o tlog não registra o encerramento: uma sessão ociosa fechada sem nova saída, ou ainda aberta, termina no último dado. Ociosa quer dizer sem dados gravados, então um comando silencioso, como `sleep` ou uma compilação sem saída, também aparece assim. Com a selo **parcial**, faltam pedaços, e o que parece pausa pode ser dado ausente.
- **Busca por texto:** uma frase dividida entre dois pedaços não é encontrada. O selo "incompleta" fica oculto nessas buscas, porque elas retornam só parte dos pedaços.
- **Filtro por período:** seleciona pedaços pela hora gravada no tlog, então a sessão aparece se algum pedaço cair no período.
- **Dados nos alertas:** o agente não lê mais o log do tlog, e as regras de `collector/wazuh-local_rules.xml` não geram alerta dele. Por isso, não há alerta de início de sessão. Só adicione `collector/ossec-agent-localfile.xml` e suba a regra `100501` para nível 3 aceitando que o texto do primeiro pedaço vá para `wazuh-alerts-*`, onde quem lê alertas o vê, mesmo sem acesso a `tlog-*`. Alertas gerados por versões anteriores continuam lá até a retenção apagá-los.
- **Entrada do usuário:** a API nunca devolve `in_txt`, mas o que é digitado costuma aparecer em `out_txt`, porque o terminal ecoa o texto. Prompts sem eco, como o de senha do `sudo`, não aparecem.
- **Auditoria:** cada replay aberto gera a linha `Replay aberto` no log do dashboard, com o usuário e a sessão. Quem lê o índice direto não passa pelo plugin: para cobrir isso, ative os logs de auditoria do indexador.
- **Segurança:** os achados, as correções e os riscos que continuam estão em [analise-de-seguranca.md](analise-de-seguranca.md).
- **Integridade:** o aviso de pedaços ausentes ou repetidos ajuda, mas não prova que a gravação não foi alterada.
- **Interface:** não há links diretos para uma sessão nem paginação da lista (máximo de 500 sessões).
