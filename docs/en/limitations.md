# Known limitations

[Português](../limitacoes.md)

- **Agent menu and home card:** the Wazuh dashboard does not let other plugins add items to these screens, so the plugin inserts them into the page, without changing Wazuh platform files. The card is a clone of **IT Hygiene**. An update can make the items disappear; the app stays reachable from the sidebar. The agent item cannot be pinned like the native tabs.
- **Sessions per agent:** the link uses the hostname from the Wazuh agent inventory, compared with the `host` recorded by tlog. If they differ, such as a short name and an FQDN, the sessions do not appear. If two hosts have the same hostname, their sessions get mixed. A newly registered agent can take a few minutes to enter the inventory.
- **Long sessions:** each replay loads at most 20,000 chunks or 64 million characters, and warns when it cuts the rest. The server analyzes up to 6 recordings at once and answers 429 when more than 200 are waiting. The list of critical commands in a session shows up to 200 events and says how many were left out.
- **Critical commands:** the search reads the terminal echo, only on lines with one of the prompt formats turned on in the settings. It does not see `ssh host command`, scripts, obfuscated content (an `rm` in `base64 | sh` only appears as a pipe to a shell) or custom prompts outside those formats, such as `❯`. **No event does not prove that nothing critical happened.** A listed command was typed, but it may have failed. Using Tab to list options can repeat an item.
- **Link to alerts:** there is no common identifier between an alert and a session. The link uses host, user, command and the time of arrival at the Wazuh manager. Simultaneous sessions of the same user, or an agent that was offline, can leave alerts unlinked. An SSH jump is only recognized on the same host; between hosts, the destination only shows the source IP.
- **Stronger evidence with `auditd`:** the tlog `session` field seems to be the same as `ses=` in `auditd`, which would link each executed command to the exact session. The Wazuh manager interpreted this field in a sample line (rule 80792), but the complete flow and the volume of alerts were not tested, because the test container does not allow `auditd`.
- **Player clock:** the player shortens pauses to at most 2 s, or the configured value, so the time shown in it is not the real duration. Jumps use markers, which follow that shortening. The real time is in the replay title.
- **Timeline:** shows the start, the stretches with recorded data and the pauses from the configured time on (30 s by default). The end comes from the SSH session-closed alert, if there is one. Without it, it is the last recorded output, because tlog does not record the end: an idle session closed with no new output, or still open, ends at the last data. Idle means no recorded data, so a silent command, such as `sleep` or a build with no output, also appears that way. With the **partial** tag, chunks are missing, and what looks like a pause may be missing data.
- **Text search:** a phrase split between two chunks is not found. The "incomplete" tag is hidden in these searches, because they return only some of the chunks.
- **Period filter:** it selects chunks by the time recorded in tlog, so a session appears if any of its chunks falls in the period.
- **Data in alerts:** the agent no longer reads the tlog log, and the rules in `collector/wazuh-local_rules.xml` do not generate alerts from it. That is why there is no session-start alert. Only add `collector/ossec-agent-localfile.xml` and raise rule `100501` to level 3 if you accept that the text of the first chunk goes to `wazuh-alerts-*`, where anyone who reads alerts can see it, even without access to `tlog-*`. Alerts generated by earlier versions stay there until retention deletes them.
- **User input:** the API never returns `in_txt`, but what is typed usually appears in `out_txt`, because the terminal echoes the text. Prompts with no echo, such as the `sudo` password prompt, do not appear.
- **Audit:** each replay opened generates a `Replay aberto` line in the dashboard log, with the user and the session. Anyone reading the index directly does not go through the plugin: to cover that, enable the indexer audit logs.
- **Security:** the findings, fixes and remaining risks are in [security-analysis.md](security-analysis.md).
- **Integrity:** the warning about missing or repeated chunks helps, but it does not prove that the recording was not altered.
- **Interface:** there are no direct links to a session and no pagination of the list (500 sessions at most).
- **Language:** the dashboard log stays in Portuguese, and the error message of the fixed loader, shown only if the app fails to load, also stays in Portuguese. The language choice is per browser, so it does not follow the user to another computer. Rule names in Wazuh alerts appear as the manager generated them.
